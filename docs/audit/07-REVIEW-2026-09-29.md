# 07 — Pre-launch review, 2026-09-29

A full review of the site before launch, from seven angles at once: security,
SEO and HTML5, performance and Next 16 conventions, backend and data flow, the
database, translation/RTL/UX, and QA/frontend. Each reviewer read the code (the
database reviewer also queried the live project, read-only) and verified every
finding before reporting it. The fixes followed in four parallel streams with
separate file ownership, then were integrated and checked together.

This file records **what was found, what was done, and what is left**. The
running state of the project stays in `docs/PROGRESS.md`.

## Security

| Finding | Severity | Done |
|---|---|---|
| Next 16.3.1: unauthenticated RCE in `/_next/image` with AVIF, which the config enables (GHSA-2xp9-vwfh-vxw4) | Critical | Next 16.3.7 |
| sharp (libheif) and tiptap (`__proto__` attribute injection) advisories | High | sharp 0.35.5, tiptap 3.31.3 |
| Every new `auth.users` row became an **active** editor — with public sign-up on, anyone could reach `/admin` | High | `drizzle/0012`: new profiles start inactive; `inviteUser` activates the invited one. **Also turn off public sign-up in Supabase Auth.** |
| An editor could redirect application notifications to their own address, or switch off consent | High | Changing `notifyEmails`, `retentionMonths` or `requireConsent` needs `submissions.handle` |

## Backend and data flow

- Races: admitting from the waiting list and erasing an application could each
  move the place counter twice. Both are now conditional updates.
- Shortening a form's retention now shortens it for the applications already
  stored, in the same transaction, and the audit says how many moved.
- A vacancy and its portal form stay in step: created together in one
  transaction; a changed deadline moves the form's closing time; unpublishing
  or archiving the vacancy takes the form down.
- The retention purge always removes the files it was given, and a media upload
  whose database row is refused no longer leaves an orphaned object.
- Resend API errors are no longer silently dropped.
- Phone numbers: a local `0599…`, spaces, dashes and Arabic-Indic digits are
  now accepted and normalised; the organisation's own numbers keep their
  formatting.
- Cache: renaming a programme refreshes project cards; one job application no
  longer clears every careers page at once.

## SEO and HTML5

- About twenty pages had no share image (a page's `openGraph` replaced the
  site-wide card). Every page now names its card.
- The language switcher sent detail pages to a slug that does not exist in the
  other language; those pages now redirect permanently to the right slug, and
  the switcher is in the server HTML.
- Sitemap: six missing pages added; noindexed records and unwritten legal pages
  removed; `lastModified` on static entries.
- JobPosting: not emitted for closed vacancies; `validThrough` in Palestine
  time; invalid `inLanguage` removed. Breadcrumb JSON-LD includes the current
  page. RSS autodiscovery restored.
- Dates: "closed", "open" and deadlines use the Asia/Gaza calendar everywhere,
  in the database too (`0011`), so a vacancy no longer shows as open for hours
  after its form stopped accepting applications.
- `<time>`, `<address>`, heading order on list pages, and image alt text that
  falls back to the record title.

## Translation, RTL and UX

- Arabic plurals: counts use `Intl.PluralRules` («مشروعان»، «3 مشاريع»،
  «11 مشروعاً») instead of one template.
- Terms made consistent: شاغر (the vacancy), فرصة (a portal form), الرسائل
  الواردة (the general inbox, distinct from job applications).
- Untranslated `FULL_TIME` shown to visitors; «وصلتنا رسالتك» shown to job
  applicants; Latin "MB"; Eastern and Western digits mixed in the catalogue —
  all fixed.
- Arabic eyebrows and badges were set in a Latin-only monospace font; the font
  stack now falls back to IBM Plex Sans Arabic without letter-spacing.
- Turnstile rendered only on the first page load and could not be retried
  after a refusal; it now renders explicitly and resets after a failure.
- Country is a localised list instead of a two-letter code; conditional fields
  explain themselves; minimum lengths are stated.
- Designed loading screens for every public route that lacked one; an admin
  error page and 404 inside the admin shell; `retry` instead of `reset`.

## Left open, with reasons

| Item | Why it is not done |
|---|---|
| Sensitive portal answers (national ID and similar) are stored as plaintext jsonb; complaints are encrypted | Needs a schema change and a key-handling decision; access is already gated and audited in the service |
| Rule 7 and Turnstile: no public form can be submitted without JavaScript, because a missing captcha token is refused | An owner decision: amend rule 7, or accept token-less posts behind a stricter limit |
| JobPosting `addressCountry` | `organization_settings` has no country column; adding one is a content decision |
| App icons and manifest icons | Only `favicon.ico` exists; the artwork has to come from the organisation |
| Drizzle journal stops at 0008 | Migrations are applied by `scripts/apply-pending-migrations.ts`; the journal needs a snapshot per migration before `drizzle-kit generate` is safe |
| Admin list editors (social links, channels) need JavaScript | A `<noscript>` notice explains it; named inputs need the action reworked |
| A new field reusing a deleted sensitive field's key would show its old answers | Needs a key-reuse check |
